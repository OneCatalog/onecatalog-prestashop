# Ответы PrestaShop-разработчику — OneCatalog Import

Решения по вопросам из [integration-plan.md](integration-plan.md) — фиксируем ДО кода.
Платформа: **PrestaShop 8.x** (совм. 1.7.8+), стандарт **v1.2**.
Легенда: 🟢 решено · 🟡 решено с оговоркой/подтвердить у владельца магазина.

---

### 1. Хранение public_id 🟢
Своя таблица **`onecatalog_map`** (`id_product` UNIQUE, `public_id` UNIQUE). Идемпотентность
по ней, не по `reference` (`reference` — артикул, §5.2). У товара PrestaShop нет штатных
произвольных полей; правка public_id вручную — через будущую колонку/поле (как в WC/Bitrix).

### 2. Мультиязычность 🟡
Контент (name/description/features/tags) пишем на **все языки магазина** (импорт
одноязычный — дублируем; полноценный мультиязык — общий бэклог стандарта). Язык запроса
к API — настройкой; карта `lang`→`id_lang`.

### 3. Единицы 🟡 подтвердить
Вес: г → **кг** (`Product.weight`). Размеры: мм → единица магазина (по умолчанию см) в
`width/height/depth`. Универсальный конвертер `Units`. Подтвердить единицы целевого
магазина.

### 4. Промо (B2B) 🟡
`promo_price` (0 < promo < base) → **`SpecificPrice`** (reduction по фикс-цене; без дат =
бессрочно, `from`/`to` = `0000-00-00`). Базовая → `Product.price`. (Каталожный импорт цену
не задаёт, §5.6; это только §13.)

### 5. Остаток (B2B) 🟡
Суммарный остаток по складам фида → **`StockAvailable::setQuantity`** (для товара,
магазин текущего контекста). Комбинации (combinations) не трогаем (импортируем простые
товары); мультимагазин — остаток в контексте по умолчанию.

### 6. Расписание §13.6 🟡 подтвердить
Авто-синк — через **cron-таск** (URL admin-контроллера с токеном) + планировщик хостинга,
или модуль PrestaShop Cron Tasks. Ручной запуск (степпер) работает всегда без cron.

### 7. Версия / API 🟢
PrestaShop **8.x** (и 1.7.8+). Конфиг — `HelperForm` в `getContent()`; операционные
страницы — `ModuleAdminController` + вкладки (Tab). Symfony-контроллеры не используем
(классический модульный API — максимум совместимости 1.7.8+/8.x).

---

## Блокеры (🚫) — решения
- **Нет произвольных product-полей** → служебные данные в своих таблицах
  (`onecatalog_map`, `onecatalog_meta`, `onecatalog_media`, очередь/лог).
- **Features = имя/значение по языку** → принимаем (find-by-name по имени feature и
  значению), как у OpenCart-атрибутов; строгий ручной маппинг — опционально позже.
- **Цена/остаток — отдельные сущности** → `SpecificPrice`/`StockAvailable`, не поля товара.

## Что подтвердить у владельца магазина
- Версия PrestaShop = 8.x (или 1.7.8+); единицы веса/длины магазина; языки (id_lang).
- Настроен ли cron (для §13.6 авто-синка). Используются ли комбинации товаров.
